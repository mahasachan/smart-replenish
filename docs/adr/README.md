# Architecture Decision Records

Use this directory for consequential, project-specific architecture decisions. Read relevant ADRs before proposing a design change. If a change conflicts with an accepted ADR, surface the conflict and obtain human direction rather than silently overriding it.

Create the next sequential filename, for example `0001-use-postgresql.md`, from `template.md`. Keep records concise and append new decisions; mark a superseded ADR and link its replacement instead of rewriting history.

An ADR should explain context, decision, considered alternatives, and consequences. Use `Proposed` while awaiting approval and `Accepted` only after a human approves it. Routine local implementation choices do not need an ADR.
